## Slice 0: Project skeleton & tooling (2026-09-29, commit `a5a48ea`)

### Departures from the plan
- **Scaffold output not kept.** The plan said to use XcodeBuildMCP `scaffold_ios_project` if it's enabled. It is, but its template is dated: Swift 5, iOS 18.4 deployment target, a workspace plus a `FancyClawPackage/` layout, no widget target, and extra `.cursor`/`.github` rules files. I used its output only as a reference and wrote `FancyClaw.xcodeproj/project.pbxproj` by hand. Object IDs follow a readable `FC00…00NN` scheme. Don't re-run the scaffold on top of this project.
- **No `.xcworkspace`.** It's a plain `FancyClaw.xcodeproj` that references `Packages/FancyClawKit` through `XCLocalSwiftPackageReference`, and the XcodeBuildMCP defaults use `projectPath`, not `workspacePath`.
- **No app-level `FancyClawTests` target.** The Architecture diagram lists `FancyClawTests / FancyClawUITests`, but every unit test lives in the package (`<Module>Tests` for each of the six modules), and `FancyClaw.xctestplan` pulls them in. Only `FancyClawUITests` exists on the app side. Add an app-level unit test target only if app-target code (App Intents in Slice 10, say) needs tests that can't live in the package.
- **App Group not verified.** Both targets declare `group.com.zacisnotacompany.fancyclaw` in `Config/*.entitlements`, and the simulator build succeeds. But simulator builds are ad-hoc signed and don't validate App Groups or the team, so we still don't know whether team `NWV8LZ45D5` is a Personal Team. **Resolve this before Slice 10.**
- **iOS 26 simulator runtime not added.** The plan marks this optional. I skipped it because of disk space, so the deployment-target floor (iOS 26.0) is still unchecked, and everything so far has run on iOS 27.0.

### Choices the plan left open
- **iPhone, portrait only** (`INFOPLIST_KEY_UISupportedInterfaceOrientations_iPhone`). The plan only says "iPhone only", so this is easy to revisit.
- **App and widget targets default to `MainActor` isolation** (`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, `SWIFT_APPROACHABLE_CONCURRENCY = YES`, member-import visibility on), matching Xcode 26+ templates. **Package modules don't use default isolation**, so mark it explicitly there (`actor`, `@MainActor`).
- **The package is iOS-only** (`platforms: [.iOS(.v26)]`, tools 6.2, Swift 6 language mode), so there are no fast `swift test` runs on the macOS host and all tests go through `test_sim`. Adding macOS would mean `#if canImport(UIKit)` guards in DesignSystem and similar code.
- **Info.plist:** `GENERATE_INFOPLIST_FILE = YES` for the simple keys, plus partial plists (`Config/FancyClaw-Info.plist` and `Config/FancyClawWidgets-Info.plist`) for the array and dictionary keys (`NSBonjourServices`, `NSAppTransportSecurity`, widget `NSExtension`). ATS combines `NSAllowsLocalNetworking` with an `NSExceptionDomains` entry for `ts.net` (subdomains, insecure loads). Tailscale CGNAT addresses are bare IPs, which ATS doesn't restrict.
- **`Config/` is a synchronized group that belongs to no target.** It's there only so the xcconfig base-configuration anchor and the plist/entitlements paths resolve. Don't add it to a target, or its plists get copied as resources.
- **Placeholder symbols** give each module something to test: `ProtocolVersion` (`current = 4`, `pinnedRelease = "2026.9.6"`, as the Risks section asks), `GatewayDefaults`, `SessionKey.main`, `SharedContainer.appGroupIdentifier`, `LaunchArgument` (`-FakeGateway`, `-DemoConversation`), `Spacing`, and `MarkdownText`, a thin wrapper over Textual's `StructuredText`. Replace or extend them freely in later slices.
- **XcodeBuildMCP session defaults aren't persisted to `.xcodebuildmcp/config.yaml`,** because the project path is an absolute worktree path. Set them each session (see `CLAUDE.md`).

## Slice 6: History, sessions drawer, and SwiftData cache (2026-09-29)

### Choices the plan left open
- **History belongs to each `ConversationStore`.** The store loads cached canonical entries synchronously, pages older messages with `nextOffset`, merges overlapping entries by Gateway ID, and persists its cursor and page state. Reconnect uses delta catch-up; reset/unknown cursor responses refetch the tail. Older pages cannot roll the cursor backwards. A changed session ID during paging triggers a fresh tail request and discards old run/outbox state. Late responses from invalidated conversations cannot restore deleted history.
- **The app retains a conversation store for each visited session.** Switching chats preserves active streams and unconfirmed echoes. The lifecycle resync restores the connection-scoped roster subscription and catches up visited conversations, rather than capturing the main conversation at activation.
- **The SwiftData container uses the existing App Group.** `CachedSession`, `CachedMessage`, and `CachedHistory` store canonical Codable payloads and ordering/page metadata, namespaced by Gateway URL. Media URLs/artifact IDs are retained; inline data URLs and unknown content payloads are dropped. Credentials remain in Keychain. Debug launch modes use an in-memory container. On a saved-profile cold launch, cached chats appear before the network connection finishes; a failed connection leaves them readable with foreground/manual reconnect available.
- **Roster reconciliation waits for the full list.** Partial pages and filtered search results upsert without treating absent rows as deleted. The final roster page prunes obsolete cached sessions and transcripts. Search filters loaded rows immediately and performs a debounced `sessions.list` query for matches outside the loaded page; its timing uses injected `GatewayTiming`.
- **Selecting another agent creates a new chat for that agent.** Existing-session agent reassignment is not a model preference patch. The pill labels this action as “Agent for a new chat”; model selection patches the current session using the provider-qualified model ID. Session mutations carry `expectedSessionId` when known.

The confirmed Delete action first patches `archived:true`, then deletes the transcript with `archivedOnly:true`, avoiding an additional admin scope. A failure is shown in the drawer; the user can retry.
- **A Load older messages button supplements scroll-to-top paging.** It makes paging discoverable and accessible. Prepending a page restores the previous first visible entry rather than jumping to the bottom.
- **The owner’s real Gateway was not used for the optional post-Slice-6 manual check.** All integration and UI tests run on throwaway FakeGateway ports with ephemeral identities. QR approval/network-loss testing against the owner's Gateway remains opt-in.

## Slice 8: Attachments (2026-09-29)

### Choices the plan left open
- **The attachment pipeline is an actor in ChatCore.** Security-scoped file reads, ImageIO decoding/downsampling, JPEG encoding, thumbnail generation, base64 encoding, and full-frame size checks run off the main actor. ImageIO detects image bytes; UniformTypeIdentifiers supplies file MIME types from extensions, with an octet-stream fallback. Images are normalized to JPEG, with orientation applied and source metadata omitted. The pipeline starts at a 2048-pixel maximum dimension, reduces quality and dimensions until both image and general file limits are met, and rejects unreadable or oversized inputs.
- **Draft attachments belong to each ConversationStore.** The composer offers Photo Library, Take Photo, and Choose File, with a horizontally scrolling thumbnail/file tray and named remove buttons. It permits attachment-only sends, shows preparation progress, and keeps the draft when preflight fails. Once submitted, the optimistic echo and retry outbox own the prepared bytes; retries reuse the same payload and idempotency key. Confirmed canonical history replaces them with Gateway media references/file metadata. No attachment bytes or base64 enter SwiftData.
- **Gateway policy is retained on the connection and updated on every handshake.** Preparation reads its attachment limits, and each send/retry validates again, including base64 expansion, JSON escaping, text, and the request envelope against `maxPayload`. Older Gateways without attachment limits use conservative local ceilings of 10 MiB per file and 5 MiB per image. File reads additionally have a 100 MiB local import ceiling before image preparation, to bound memory. Animated image input becomes a still JPEG of the first frame.
- **Camera capture uses the planned UIImagePickerController wrapper.** It requests camera permission when selected, reports denied access and unavailable hardware, and supports cancellation. The existing camera usage description now includes chat photo capture; PhotosPicker needs no blanket photo-library permission.
- **`-DemoAttachments` provides a deterministic draft for UI checks.** It uses an ephemeral FakeGateway, generated image bytes, and a text file. FakeGateway records attachment payloads and returns canonical media metadata without embedding upload bytes. No dependency or test target was added.

## Slice 9: Exec approvals (2026-09-29)

### Choices the plan left open
- **A single `ApprovalStore` belongs to the Gateway connection**, rather than each visited conversation. It listens independently of chat selection, retains transient cards across session switches, and supplies pending counts to the Chats button and session drawer. Cards appear in the matching chat transcript and show the full command, optional preview, directory, host, warning, and expiry countdown. Commands and decisions are not written to SwiftData.
- **Requests without a session key use their run ID when an observed chat/agent event identifies the run.** Requests with neither association remain visible in every chat with an explicit “Gateway did not identify a chat” explanation; they are never silently attributed to the current chat.
- **Resolve races are terminal and idempotent.** A decision disables every copy of the card while its RPC is in flight; resolved events win over late responses/errors. Duplicate requests cannot reopen a handled card, including resolved events observed before the request. `APPROVAL_NOT_FOUND` displays “Already handled elsewhere or expired.” Network failures leave an unexpired request retryable.
- **Expiry uses injected `GatewayTiming` and wall-clock time**, since Gateway deadlines are absolute milliseconds. A one-second update refreshes countdowns and badge counts without incoming events. Expired cards remain readable and cannot send a decision. Foreground/reconnect resync refreshes expiry and the negotiated scopes.
- **The existing handshake already requests `operator.approvals` and advertises exec approvals.** The store checks the granted scopes; absent scope or `MISSING_SCOPE` disables decisions and explains that the owner must grant `operator.approvals` and reconnect. Known allowed choices are deduplicated, unavailable/unknown choices are excluded, and Deny remains available. The outbound resolve encoder rejects unknown decision values.
- **Approval state is event-driven.** No pending-approval recovery RPC is specified in this slice. Observed requests stay in memory until handled or expired; requests missed while disconnected or before app launch are not reconstructed from cached history. Handling them through the Gateway remains necessary in those cases. Plugin approvals remain outside this exec-only slice.
- **`-DemoApprovals` uses an ephemeral FakeGateway and two sessions.** FakeGateway now records resolve payloads, resolves seeded requests, emits resolved events, and can return scripted RPC errors. No new dependency or test target was added.

Recheck this if the package layout or toolchain changes.

### Choices the plan left open
- **Actions open the main app and require local authentication.** `AppDependencyManager` provides the existing app model through injected services, avoiding a second socket or extension credential access. Preparation is coalesced across the root view and an intent. Ask targets `agent:main:main`, uses the normal outbox/idempotency path, adopts the server run ID, subscribes before sending, and only consumes its matching run/session. Yielded finals keep waiting; abort/errors propagate. After 25 seconds following acknowledgment it returns a continue-in-app message without canceling the remote run. Empty/busy/unavailable chats do not send. This is a foreground Shortcut, with no promise of unattended Siri operation while locked or background execution.
- **Cached entities stay local and Gateway-specific.** Suggestions use the 20 most recent non-archived cached sessions; search covers the full cache. IDs include the Gateway URL, and saved entities from a different/forgotten Gateway fail resolution. Opening a cached chat can work offline with a configured connection; Ask/New Chat require a connected Gateway. `fancyclaw://session?key=…` handles Live Activity taps after validating the route and current cached session.
- **Local Live Activities report uncertainty when updates stop.** A connection-wide listener follows runs even when the user switches chats. The reducer handles independent lifecycle/chat sequences, yielded replies, terminal events, disconnects and foreground history catch-up. Repeated token deltas do not issue identical ActivityKit updates; the system renders elapsed time. Background/disconnect displays “Open FancyClaw to refresh”, since there is no push delivery or reliable background WebSocket. Terminal state ends the activity; explicit disconnect clears activities, and cold launch ends orphaned ones. Transcript text, tool commands and credentials are excluded from activity state.
- **ActivityKit stays in the app driver.** The SDK's `Activity` type is non-Sendable. The main actor stores only IDs; concurrent helpers look up and update/end activities in their own isolation region. No unchecked Sendable or preconcurrency escape is used. Driver deliveries are serialized so a late streaming update cannot overwrite a terminal state.
