# Redesign R4: Home

Date: 2026-10-03. Plan: `layout_redesign.md`, Slice R4. Status: implemented, independently reviewed, compiled and verified; one full-plan demo-startup failure passed on unchanged focused rerun and remains logged.

## Implementation

- Home replaces the foundation placeholder with a time/date greeting and profile avatar, Gateway status/reconnect pill, new-task prompt with existing attachment preparation, model menu, pending command reviews, active-run cards with spinners, and five recent sessions. The avatar retains `home.settings`; new controls use `home.*` identifiers.
- The default agent is retained independently of the chat title picker's selected agent. Home explicitly creates with that default ID; nil omits the wire key and lets the Gateway choose. Names come from the Gateway, falling back to capitalized agent IDs or Assistant while no default has been reported.
- `HomeTaskDraft` owns only ephemeral text, attachment bytes and model choice. The first submit freezes text, uploads, agent, model, creation key, send key and eventual session/incarnation. Create/model/send failure retains the draft. Retry uses its original session/key/payload. An explicit, confirmed “Edit as a new task” unlocks the draft and pauses automatic retry of the original failed send; the original chat remains manually retryable. Reset/delete invalidates a frozen attempt even if its session ID was omitted.
- `ConversationStore.sendAcknowledged` preserves existing composer `send()` semantics. Same-key retries reuse the outbox row; concurrent retries join keyed acknowledgment waiters. Canceling a waiter removes only that waiter. Exact pending user identities, including the canonical `:user` suffix, confirm acceptance before reconciliation removes the outbox entry. Assistant/lookalike/unrelated-session entries cannot confirm it. Confirmation settles joined waiters immediately and wins over a delayed RPC error. Reset/invalidation clears confirmation state and settles waiters.
- Create/model APIs return canonical RPC success even if the private cache write then fails; a visible cache error remains. No additional persistence abstraction was introduced solely to inject cache failures.
- `RunActivityStore` is observable and exposes current runs plus terminal IDs. Home merges roster flags/IDs and activity-only sessions into one card per session, excludes archived sessions and known terminal IDs, and prefers live Replying/Finishing state to a Thinking fallback. Approval details reuse the R2 title rule. Missing-session commands open a full approval sheet using live store state.
- Pull to refresh resyncs the connected app and catalogs. Offline text remains editable, cached sessions remain available, and attachment/model/send controls are disabled with a reconnect affordance. Empty Recent and create/patch/send errors have explicit copy.

## Choices and limits

- Home opens the chat **after acknowledgment**, instead of the plan's literal open-then-send order, so rejected submissions leave the error and original draft visible on Home.
- The menu's default is **Gateway default**, represented by no model patch. In pinned OpenClaw 2026.9.6, `models.list.defaultModels` contains `automaticUtilityModel`, not the conversational primary; neither that utility model nor the first configured model is inferred as the chat default.
- Recent uses the unsearched Gateway roster with archived sessions excluded. A search left in Chats must not filter Home.
- A nil-ID session invalidation event provides the missing incarnation signal; retry also compares a present ID against the current roster. Profile disconnect replaces the ephemeral Home draft.
- The pinned source `dist/sessions-create-Drr0cz5R.mjs` wraps creation in a principal/device-owned idempotency cache, checks exact request parameters and authorization, joins in-flight creation, and reuses successful results. Retention is **five minutes** (`SESSION_CREATE_IDEMPOTENCY_RETENTION_MS = 3e5` in `src-BRUl7oDv.mjs`), held in Gateway context memory. Stable creation keys protect retries within that retention/context lifetime; they do not establish an indefinite guarantee across Gateway restart or expiration. FakeGateway models successful same-key result reuse and changed-parameter rejection without production retention eviction.
- Cards keep opaque theme bases under glass for stable appearance. Only spinners indicate running state; no timers/progress bars.
- Per owner steering, no new accessibility audit tests were added. Semantic fonts, control labels and scaled layout values remain. Functional/UI verification and appearance screenshots remain required.
