# Redesign R2: Chat restyle

Date: 2026-10-02. Plan: `layout_redesign.md`, Slice R2. Store logic is unchanged; this is presentation, plus one media-download seam.

## What shipped
- **Top bar** (`ChatTopBar`): glass back button (`chat.back`), centered `AgentAvatar` with title (tap opens the agent/model menu, `chat.agentModel`), glass ••• menu (`chat.menu`) with Rename, Reset, Delete (confirmation), all through `SessionStore`. Navigation and tab bars hidden; the edge-swipe back gesture is re-enabled (`enableSwipeBack`). Content scrolls under a top fade. `AgentModelPicker` is now `AgentModelMenuContent`; the picker above the composer is gone.
- **Messages:** accent user bubble (22 pt corners, 6 pt bottom-trailing, max 82% of the row, "Not sent · Retry" kept); agent text without a bubble; shimmering "Thinking…" (static with Reduce Motion); one tool-summary chip per assistant message (`chat.toolchip.<messageID>`, expands to the per-tool rows `chat.tool.<id>` with the existing arguments/result disclosure); file card with name, "size · type" and a download button; 22 pt image cards; approval card with a one-line receipt once resolved.
- **Input bar:** floating 54 pt glass capsule in `.safeAreaInset(.bottom)`, "+" attachment menu unchanged, attachment tray above the capsule, send (arrow up) that becomes Stop while streaming. No waveform.
- **Pure, unit-tested logic (ChatCore, `ChatPresentation.swift`):** `ToolSummary.make(for:)`, `ConversationApproval.displayTitle` (commandPreview, else warning, else "Run a command"; R4 should reuse it) and `.receipt`, `ContentBlock.Media.fileDetail`/`fileTypeLabel`/`safeFileName`. Tests: `ChatPresentationTests` (7).
- **File download:** `GatewayConnection.fileData` / `ConversationStore.fileData` reuse the media path (artifact download or Gateway URL, same origin/bearer/redirect/25 MB policy). The only change inside the connection is `fetchMedia(_:imageOnly:)`, which relaxes the `image/*` Accept header and MIME check for file downloads. The card writes the bytes to a temporary directory (complete file protection), opens Quick Look, and removes the directory when the preview closes or the card disappears. Nothing is cached or persisted. Cards without a URL or artifact id show no download button.
- **Approval haptics:** success on approve, warning on deny, only when `hapticsEnabled`.
- **Approval focus:** see below.

## Approval focus verification and fix
The R1 `.task(id: focusApproval)` was not reliable: the transcript had no `.scrollTargetLayout()` (so `scrollTo(id:)` could not resolve ids in the lazy stack), and it ran once, before history loaded. `AppModel.open` pushes the route first, then loads history. Fix: `.scrollTargetLayout()`, plus a focus mode that re-aims at `approval:<id>` after message count, approval list or history-loading changes, and ends when the person starts scrolling (`onScrollPhaseChange`). While focusing, follow-latest and load-older-on-top are suppressed. New debug mode `-DemoApprovalFocus` opens a not-yet-loaded 60-row chat focused on its approval; `testFocusedApprovalStaysInViewWhileHistoryLoads` asserts the card's Approve button is hittable above the composer. I did not run the old code to confirm it failed (inferred from the missing scroll target layout); the new test passes.

## Choices and deviations
- **No ambient glow behind the chat.** The transcript uses the flat theme base, and the approval card is a flat accent tint (18%) rather than tinted glass. Both the glow and tinted glass made the accessibility audit's contrast fail on chat text. Glass remains on the top-bar buttons, composer capsule, and ••• / back controls.
- New DesignSystem helper `View.surface(in:fill:opacity:)` (flat tint over an opaque theme base) for chips, cards, tray, code blocks. `MarkdownCodeBlock` header/body and `AgentAvatar` text color changed accordingly (avatar initial is now dark; white on the orange gradient failed contrast).
- Composer placeholder is "Message" (design's "Ask a follow-up" doesn't fit a first message).
- Tool summary wording: "Ran x" / "Running x" / "x failed" / "x ended" for one tool; "Used N tools" / "Using N tools · 1 running · 1 failed" for several.
- Approval decisions are ordered Deny, Always allow, Approve and are 44 pt tall (design says 40).
- The demo Gateway supplies OpenClaw and Helper agents and a Fake model. The review regression now selects the model and checks the current session's spoken model value, then selects Helper and verifies a new empty chat for that agent. The ••• menu and Reset confirmation are also UI-tested.
- `RichConversationDemo` gained a file message (`gateway-summary.md`) so the file card appears in screenshots. Real Quick Look presentation is still not exercised by a UI test; the reviewed temporary-file owner now has asynchronous cancellation, retry, sanitized-file-content and cleanup unit tests, and the Gateway file download path has a stubbed non-image MIME and origin-bound credential regression.
- Existing UI tests migrated: tool tests expand the chip first; approval receipts are found via `approval.status.<id>` (label starts with "Approved"/"Denied"); `goBackToTab` uses `chat.back`. ApprovalTests now waits for the Approve button to become enabled (the card can appear before approval scopes are known; it failed once in a first run).

## Independent review and corrections (2026-10-02)

- **Temporary preview lifecycle:** the original untracked download task could finish after its card disappeared, write an orphaned temporary file, and present Quick Look after navigation. `TemporaryMediaDownload` in ChatCore now owns a cancellable task and its temporary preview. Cancellation discards even an uncooperative provider's late bytes before writing; dismissing the preview or leaving the card removes its directory. It retains only transient state and does not use the transcript cache.
- **Moved session-action errors:** Rename, Reset, Delete and model changes report failures through `SessionStore.errorMessage`, which was invisible in the chat. ChatView now shows a dismissible `chat.sessionError` banner. `-DemoSessionActionError` uses FakeGateway to reject a model patch; the UI regression verifies the error, the unchanged selected model, dismissal, and a subsequent reported failure.
- **Header and input geometry:** the empty multiline field's vertical `fixedSize` reserved five lines, making the default composer about 95 points tall. Removing it and keeping a 44-point field target restores the 54-point capsule while allowing multiple lines. The title menu now contains only title glyphs, preserves native Menu/Button semantics and a 44-point label target, and wraps at large sizes. The avatar sits outside its label. The header base is fully opaque and the transcript has a physically clipped viewport below it; reviewed screenshots show no ghosted text behind the status bar or header. The bottom composer remains a safe-area inset.
- **Branding and accessibility:** nameless/blank Gateway agents fall back to the capitalized agent id. Chat's avatar exposes the agent name as one image element; avatars remain decorative by default elsewhere. This also investigates the audit's elementless "Potentially inaccessible text" finding, but causality is not established. The approval audit waits for scoped decision buttons to be enabled. Filenames use semibold text and the approval eyebrow uses the primary token. Audits continue to check all issue types without suppression.
- **Markdown palette:** Textual remains the renderer. Its syntax palette now uses AppTheme tokens, with stronger light diff colors and a regression checking at least 4.5:1 on the actual code/card surfaces. The user bubble remains a 30% accent tint over the opaque theme base rather than the plan's solid accent fill, preserving readable text in both appearances.
- **Deterministic Settings fixture:** the old offline demo refused only one recovery attempt, so a late availability callback could consume that refusal and reconnect automatically. FakeGateway now supports a persistent connection refusal without consuming scripted hello replies. `-DemoOffline` clears it only on explicit Reconnect; the three-second startup-delay assumption is removed. A new FakeGateway regression checks repeated refusal and success after clearing it. Production Gateway reconnect behavior is unchanged.
