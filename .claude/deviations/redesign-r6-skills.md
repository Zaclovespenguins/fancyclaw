## Store, lifecycle and layout

- `SkillStore` owns one cancellable load task, coalesces concurrent callers through completion/publication, and guards publication with a generation. Disconnect cancels loads and retains an explicitly stale same-profile snapshot; explicit disconnect/profile replacement clears snapshot/search/error. A cancelled request never creates an error or publishes a late reply. Refresh errors keep the previous snapshot visible and offer Retry.
- `AppModel.resync` refreshes skills concurrently with existing session/transcript work, so a slow skill request cannot delay chat catch-up. The Skills tab renders the injected store; store identity resets local sheet state on profile replacement.
- Two-column glass tiles use theme colors and semantic fonts, reflowing to one column at accessibility sizes. Known skills use semantic theme accents; unknown skills get a stable neutral shade. Disabled decorative glyphs fade to 60% while readable text stays opaque. This departs from fading the entire tile to preserve legibility.
- Read-only detail is a sheet. It includes description, readiness/policy, separate model/command visibility, requirements/missing items and source/configuration key. No cache, credential exposure, host file path UI, or extra dependency is introduced.
- `-DemoSkills`, `-DemoSkillsEmpty`, `-DemoSkillsError`, and `-DemoSkillsOffline` use an isolated FakeGateway and source-derived fixture. Offline mode awaits the shared load before dropping its socket. Existing debug gateways reply to the new read-only RPC so launch-time refresh does not time out.
- Per owner steering, no accessibility audits or additional accessibility repair were added; semantic fonts and ordinary labels remain. See `redesign-accessibility-deferred.md` for the shared follow-up.
